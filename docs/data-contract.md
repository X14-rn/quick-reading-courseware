# JSON data contract — `qr-courseware-map/1.0`

The normative JSON Schema is [`schemas/qr-courseware-map-1.0.schema.json`](../schemas/qr-courseware-map-1.0.schema.json). All page numbers are 1-based physical positions in the exact PDF bound by SHA-256. A filename is a display label, not an identity key. The schema is strict about required fields, types and unknown properties; `src/contract.js` adds cross-record and status invariants described in the skill's `references/contract.md`.

`page_inventory` has exactly one row per physical page of every declared PDF, including administrative, scanned, blank and uninspected pages. `inspection` is `inspected`, `pending` or `unreadable`; `element_ids` names the page's SCR occurrences. Empty inspected pages are allowed with an explanatory `note`. Every SCR element must appear in its page row. This is an accounting ledger, not proof that inspection found every element.

Each SCR occurrence carries `verification` (`verified`, `pending`, `unresolved`). Pending and unresolved records require structured `uncertainty`: category, affected content, source evidence and attempted checks. A nonmapped record also requires a reason. Nodes may carry the same uncertainty shape. `complete` requires inspected pages and verified occurrences as well as a full-source ChatGPT review, no unresolved elements or critical issue, and a confirming V2 pass. The schema and validator cannot certify semantic truth; those are explicit human/ChatGPT review gates.

`v2.nodes` is the reviewed conceptual hierarchy; `v3.nodes` is an identical copy with references stored separately. A knowledge node has a stable `id`, `parent_id`, `kind`, title, objective and evidence IDs. Only `learning_point` leaves have navigation references. The source coverage register retains each occurrence separately. A reference collapses repeated occurrences on the same document/page into one button and retains all their IDs. `validation` records the review scope and unresolved problems; the viewer displays blocked maps without upgrading their status.

Example fixtures: [`synthetic-valid.json`](../fixtures/synthetic-valid.json) binds `waves.pdf` and `optics.pdf` and includes a point supported by both documents; [`synthetic-invalid-page.json`](../fixtures/synthetic-invalid-page.json) cites physical page 99 in a two-page source and must be rejected. They are synthetic test inputs, not results of ChatGPT decomposition.

Schema evolution: consumers reject unknown major/version strings. This working 1.0 contract supersedes the earlier untested draft with the same marker; no external 1.0 export has been accepted. After release, additive fields require a new schema version because `additionalProperties: false` prevents silent contract drift. Preserve ID and PDF hash identity when migrating; never silently renumber physical pages.
